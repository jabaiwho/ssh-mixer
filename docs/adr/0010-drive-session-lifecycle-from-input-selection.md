# Drive Session lifecycle from Input selection

Choosing a Playback Source in the always-visible Inputs section is the user's explicit request to start routing immediately; changing a non-empty selection applies the latest complete set through a bounded stop/start transition, and removing the final Source ends and cleans the Session. This replaces a separate generic Start control because splitting selection from activation made Source changes easy to leave stopped and obscured the primary routing controls.

A Route Mode-only change reuses the backend's persisted stable matcher set instead of resubmitting presentation choice IDs, so an output-device change cannot relabel the active choice into another Source. Capture Sources retain a stronger boundary: choosing one presents an additional per-Session confirmation before any start or restart that includes microphone audio. **End Stream** clears the current selection and performs the same ownership-safe cleanup, while Pin, Recently used, Refresh, panel opening, profile loading, wake, unlock, login, and reconnection never start audio.

The panel assigns a monotonic configuration revision to every newer Input or Route Mode choice and binds each Session apply operation to the revision it received. Completion may clear dirty state only when its operation revision still equals the latest panel revision. A Capture confirmation also owns an isolated copy of that exact desired Session—destination, Source choices, start policy, matcher-reuse policy, and revision—and activation queues only that copy rather than rebuilding from mutable presentation state. These two boundaries preserve the confirmed destination/selection when an older start finishes concurrently or a periodic snapshot restores stale persisted presentation behind a still-visible consent prompt.
